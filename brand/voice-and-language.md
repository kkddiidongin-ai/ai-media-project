## 1. Tagline

### 1-1. 후보 (10개)

| # | Tagline | 전달하는 것 | 메모 |
|---|---|---|---|
| T1 | **AI, 해본 만큼만 말합니다** | 직접 확인 + 솔직함 | 원칙형. 가장 짧고 정확함 |
| T2 | **내 일에 AI를 쓰면, 실제로 어떻게 되는지** | 사람의 일 + 결과 | 설명형. 처음 보는 사람에게 가장 친절함 |
| T3 | **AI 소문 말고, 써본 결과** | 과장 대비 | 대비가 선명함. "소문"이 약간 공격적으로 읽힐 수 있음 |
| T4 | **AI를 믿기 전에, 먼저 해봅니다** | 확인 태도 | 신뢰 중심 |
| T5 | 해보고, 재보고, 기록합니다 | 방법 3단계 | 리듬이 좋지만 무엇에 대한 것인지(AI, 일)가 빠짐 |
| T6 | 회의록부터 리뷰 답글까지, 직접 해본 AI | 과제 예시 | 구체적. 과제가 늘면 교체 필요 |
| T7 | 된 것도, 안 된 것도 적습니다 | 실패 공개 | 차별점이 강함. 단독으로는 AI가 안 보임 |
| T8 | 매일 하는 일, AI로 해보면 | 사람의 일 | 부드러움. 확인·기록이 약함 |
| T9 | 직접 해본 AI 실용 기록 | 설명형 descriptor | 부제로 적합 |
| T10 | 오늘 하는 일에 AI를 대 보는 곳 | 일상 비유 | 재미있지만 "대 보다"가 모호함 |

## 2. Voice & Tone

### 2-1. 목소리 원칙 (항상 같음)

| 원칙 | 하는 말 | 하지 않는 말 |
|---|---|---|
| **해본 것만 경험으로 말한다** | "직접 해봤습니다." | "누구나 쉽게 할 수 있습니다." |
| **조건을 붙인다** | "무료 버전, 30분짜리 회의 기준으로는 이랬습니다." | "이 도구가 최고입니다." |
| **숫자는 잰 것만** | "기존 25분, AI 사용 12분(수정 포함)." (실측했을 때만) | "시간이 절반으로 줄어요!" |
| **모르는 건 모른다고** | "이 부분은 아직 확인하지 못했습니다." | (추측을 사실처럼 쓰기) |
| **담백한 재미** | 상황의 웃긴 점은 살린다. "세 번째 시도에서 AI가 회의에 없던 사람을 참석자로 넣었습니다." | 조롱, 과장, 밈 남발, "충격", "미쳤다" |
| **권위 대신 기록** | "지금까지 확인한 결과로는" | "전문가가 분석한 결과", "AI 전문가가 알려주는" |

- **주어**: 한국어의 주어 생략을 기본으로 한다("직접 해봤습니다"). "저희 연구팀" 같은 규모 과장을 쓰지 않는다. 필요하면 바이라인의 실제 인물이 주어다.
- **높임**: 본문은 "-습니다"를 기본으로 하고, 주간 노트와 소개는 "-어요"를 섞어 조금 더 가깝게 쓴다.

### 2-2. 상황별 톤

| 상황 | 톤 | 예시 (형식 예시일 뿐, 실제 결과 아님) | 피할 것 |
|---|---|---|---|
| **Headline (제목)** | 과제가 주어. 결과 방향은 담되 과장하지 않음. 질문형 허용 | "매주 하는 회의 정리, AI에 맡겨 보니" / "리뷰 답글 30개, 사장님 말투가 유지될까" | 숫자 낚시, "충격", "필수", "모르면 손해", 도구 이름이 주어 |
| **Article (본문)** | 차분하고 구체적. 짧은 문장. 과정은 시간 순서로 | "첫 번째 요약에는 결정 사항이 빠져 있었습니다. 질문을 바꿔 다시 시켰습니다." | 전문용어 나열, 감탄문, 일반화 |
| **Weekly (주간 노트)** | 동료에게 전하는 말투. 조금 더 가볍게. "-어요" | "이번 주에는 리뷰 답글을 해봤어요. 절반은 그대로 쓰기 어려웠어요. 이유는 본문에 적었어요." | 뉴스 요약 톤, 과한 이모지 |
| **Failure (실패)** | 담담하게. 원인과 조건, 다음 시도를 같이. 자조나 비난 없이 | "이번엔 원래 방식이 더 빨랐습니다. AI 결과를 고치는 데 시간이 더 들었기 때문입니다. 짧은 회의라면 다를 수 있어서 다음에 확인해 보겠습니다." | "AI 쓸모없다", 도구 조롱, 실패를 숨기는 모호한 표현 |
| **Correction (정정)** | 짧고 분명하게. 무엇이 틀렸고, 어떻게 고쳤고, 언제인지 | "2026-11-02 정정: 무료 버전의 월 사용 한도를 잘못 적었습니다. 공식 요금 페이지 기준으로 고쳤습니다. 판정은 바뀌지 않았습니다." | 변명, 조용한 수정, 긴 사과문 |
| **About (소개)** | 담백한 이유와 원칙. 실적 없이 방식으로 설명 | §6 초안 | 경력 과시, 비전 선언, "최고의" |

## 3. Editorial Vocabulary (독자에게 보이는 말)

내부 코드(TEST 등)는 관리표와 기획 문서에서 그대로 쓴다. 아래는 **사이트에서 독자가 보는 말**이다. 모두 가칭이다.

### 3-1. 형식 라벨

| 내부 | 독자용 권고 | 대안 | 이유 |
|---|---|---|---|
| TEST | **직접 해봄** | 해봤더니 (연재명으로) | 브랜드 핵심어를 그대로 씀 |
| TRACK | **오래 써보기** | 30일 써보기 (기간을 넣은 가변형) | "장기 추적"은 딱딱함. 진행 상태는 "진행 중 · ○일째"로 따로 표시 |
| CHECK | **주장 확인** | 진짜일까 | 뜻이 가장 분명함. "팩트체크"는 언론 기관 인상 |
| BRIEF | **변화 확인** | 써볼까? | "브리프"는 뉴스 인상 (positioning §13-2). 결론은 "써볼 만함 / 넘겨도 됨" |
| GUIDE | **알아두기** | 기초 안내 | 가볍지만 참고 자료의 역할이 분명함 |

### 3-2. 구조·신뢰 용어

| 내부 | 독자용 권고 | 비고 |
|---|---|---|
| Cluster | **(표시하지 않음)** 과제 이름만 보여줌 (예: "회의·보고") | "과제"라는 단어는 내비게이션 한 곳에만 쓰거나, §4 대안을 따르면 쓰지 않음 |
| Record | **확인 기록** | 유지. 과시적이지 않고 뜻이 분명함 |
| Method | **확인 방법** | "방법"만으로는 무엇의 방법인지 모호함 |
| Weekly | **이번 주** (메뉴) / **이번 주 노트** (페이지) / **○호** (각 호) | 유지 |
| 판정 | **결론** | "판정"은 심판 느낌. 값은 **쓸 만함 / 조건부 / 아직은 비추천**. 주장 확인에서는 **주장만큼 안 됨** (내부 "기대 미달") |
| 확인 수준 | **확인 방식** | 값은 **직접 재봄 / 직접 써봄 / 자료로 확인** (내부: 실측 / 직접 사용 / 출처 확인) |
| 확인일 | **확인한 날** / 오래되면 "확인한 지 ○개월" | Freshness 등급은 독자에게 보이지 않음 |
| Version history | **바뀐 기록** | |
| 정정 로그 | **정정 기록** | 미디어 관행 용어라 그대로 씀 |
| 남은 질문 | **다음에 확인할 것** | |
| Evidence | **근거 자료** | |
| 이해관계 | **광고·제휴 표시** (값: 제휴 없음 / 제휴 링크 있음 / 협찬 받음 / 무료로 제공받음) | |
| 혼자 해보려면 | **혼자 해보려면** | 유지 |
| 누구에게 맞나 | **이런 분께 맞아요 / 이런 분께는 안 맞아요** | |
| Research Log | (공개하지 않음) 내부 명칭 "확인 메모" | |
| 과제 허브의 "아직 확인하지 못한 것" | **아직 해보지 않은 것** | |

### 3-3. 쓰지 않는 단어 (편집 정책 §7에 추가)

"검증 완료", "인증", "공식", "연구소", "랩(Lab)", "꿀팁", "치트키", "끝판왕", "딸깍", "자동 수익", "혁명", "미쳤다", "무조건", "AI 전문가가"

## 4. Navigation Label 검수

| 현재 (5A 승인) | 검토 | 권고 |
|---|---|---|
| 과제로 찾기 | 뜻은 분명하다. 다만 "과제"는 일반 사용자에게 **숙제**처럼 들릴 수 있다 (특히 30~60대, 자녀가 있는 독자) | **대안 제안: "하는 일로 찾기"** 사용자 결정 사항. 유지해도 이해에는 문제없음 |
| 이번 주 | 짧고 명확, 재방문 습관과 맞음 | **유지** |
| 확인 기록 | 뜻이 분명하고 과시적이지 않음 | **유지** |
| 방법 | 무엇의 방법인지 모호함 | **"확인 방법"으로 변경 권고** |

→ 권고 메뉴: **하는 일로 찾기(또는 과제로 찾기) | 이번 주 | 확인 기록 | 확인 방법**
URL은 바꾸지 않는다 (`/tasks/`, `/weekly/`, `/record/`, `/method/`). 라벨만 바뀐다(site-ia §14 원칙).

## 5. Homepage Hero Copy (브랜드명 미확정 상태에서 사용 가능)

CTA는 가입이나 구매가 아니라 **탐색**이다.

| # | Headline | Supporting Copy | CTA |
|---|---|---|---|
| H1 (**권고**) | **AI, 해본 만큼만 말합니다** | 회의 정리, 메일, 리뷰 답글처럼 매일 하는 일에 AI를 직접 써보고, 걸린 시간과 비용, 안 된 부분까지 기록합니다. | 하는 일로 찾기 |
| H2 | **내 일에 AI를 쓰면, 실제로 어떻게 될까요?** | 소문이나 광고 대신, 직접 해본 결과로 답합니다. 된 것도, 안 된 것도 적습니다. | 직접 해본 것 보기 |
| H3 | **AI를 믿기 전에, 먼저 해봅니다** | 새 기능과 유행하는 활용법을 일과 생활에 직접 대 보고, 확인한 날짜와 조건을 함께 남깁니다. | 하는 일로 찾기 |
| H4 | **매일 하는 일, AI에 맡겨 보면** | 회의록부터 고객 응대까지, 직접 해본 시간과 결과를 공개합니다. 계속 다시 확인합니다. | 최근 확인한 것 보기 |

H1을 권하는 이유: 원칙(해본 만큼만)을 먼저 말하고, 보조 문장에서 과제 예시와 기록 범위(시간·비용·실패)를 모두 보여준다. 첫 화면 아래의 "어떻게 확인하나요?" 링크(site-ia §5)와 자연스럽게 이어진다.

## 6. About 핵심 문장 (초안, 실적 없음)

> 이곳은 AI를 사람이 실제로 하는 일에 써보고, 그 결과를 기록하는 미디어입니다.
> "AI로 뭐든 된다"는 말과 "별로 쓸 데 없다"는 말 사이에서, 내 일에 정말 쓸 만한지 판단할 근거가 부족하다고 느껴 시작했습니다.
> 회의 정리, 메일, 고객 응대 같은 일을 직접 해보고, 걸린 시간과 비용, 안 된 부분까지 확인한 만큼만 적습니다.
> 도구를 팔거나 수익을 약속하지 않으며, 광고나 제휴가 있으면 글 첫머리에 밝힙니다.
> AI는 계속 바뀌기 때문에 한 번 쓴 글도 다시 확인하고, 바뀐 내용은 기록으로 남깁니다.
