## 1. 한 문장 정의

> **AI를 직접 써보고, 걸린 시간과 비용을 재고, 결과(실패 포함)를 기록해서, "이게 내 일과 생활에 실제로 쓸 만한가"를 판정해 주는 AI 실용 미디어.**

- 다루는 대상은 **AI 자체가 아니라 AI 때문에 달라지는 사람의 일·생활·시간·돈**이다.
- 이 사이트의 정체성은 주제보다 **방법(직접 사용 → 측정 → 기록 → 판정)**에 있다. 무엇을 다루든 같은 방법으로 다룬다는 것이 브랜드다.

## 2. 핵심 질문에 대한 답

| # | 질문 | 답 |
|---|---|---|
| 1 | 정확히 무엇을 다루나? | 일(업무), 가게·1인 사업, 생활에서 AI를 **실제로 쓸 때 생기는 결과**, 그리고 AI에 관한 **주장·오해·위험의 사실관계**다. 기술 해설과 산업 뉴스는 이 두 가지를 이해하는 데 필요한 만큼만 다룬다 |
| 2 | 처음 발견하는 이유는? | ① 특정 문제("회의록", "리뷰 답글", "행정 서류")에서 AI를 써도 되는지 찾다가 ② "진짜 되나?" 싶은 AI 주장(수익, 기능 광고)을 확인하려다 ③ 지인·교육·카톡 공유로. Phase 1 조사상 ③이 저활용자에게 가장 현실적이고(경로 C), ①은 AI 검색 요약에 잠식되는 중이라 **공유되기 쉬운 결과(수치·판정)**가 중요하다 |
| 3 | 무료 AI 정보가 넘치는데 왜 이걸 읽나? | 다른 곳은 대부분 **"이렇게 하면 된다"(방법)**를 준다. 이 사이트는 **"해봤더니 이만큼 됐고 여기서 안 됐다"(측정된 결과)**를 준다. 시간, 비용, 실패, 누구에게 맞지 않는지가 들어 있다. ChatGPT나 AI 요약은 이 **직접 측정한 경험 데이터를 만들어낼 수 없다** |
| 4 | 검색형 블로그와 무엇이 다른가(재방문)? | 한 번 쓰고 끝나는 글이 아니라 **진행 중인 실험(TRACK), 주간 노트, 재검증 업데이트**가 있다. "다음 결과"가 존재한다(§8) |
| 5 | 운영자가 직접 해야 가치가 생기는 콘텐츠는? | TEST(직접 실험), TRACK(장기 추적), CHECK(주장 검증의 실행 부분), BRIEF의 "TRY/SKIP 판정". 이것들은 **실행하지 않으면 쓸 수 없는** 콘텐츠다 |
| 6 | AI 자동 생성 콘텐츠와 어떻게 구별되나? | 모든 대표 콘텐츠에 **확인일, 도구·버전·요금제, 실측 시간, 실제 비용, 실패, 원본 스크린샷**을 표준으로 넣는다. 자동 생성으로는 채울 수 없는 칸을 구조로 만든다(§6). 제작에 AI를 쓴 방식도 공개한다([editorial-policy.md](editorial-policy.md)) |
| 7 | 시간이 지나면 어떤 자산이 쌓이나? | ① 실험 기록 DB(같은 형식이라 비교 가능) ② 측정된 시간·비용 절약 기록 ③ 주장 검증 DB(CLAIM → 결과) ④ 참고 라이브러리(GUIDE) ⑤ 재검증 이력(같은 과제를 6개월 뒤에 다시) — §9 |
| 8 | 어떤 콘텐츠가 연구 이력을 증명하나? | 날짜가 붙은 TEST·TRACK·CHECK 목록, 실패 공개 목록, 재검증 기록, 정정 로그. "연구 기록" 페이지가 이것을 자동으로 모아 보여준다(§9) |
| 9 | 쉽지만 "초보자 전용"처럼 보이지 않으려면? | **쉬운 말은 쓰되, 내용은 측정과 판정**이다. 초보자용 "사용법"이 아니라 누구에게나 필요한 "결과"를 다룬다. 사무직 숙련자도 "회의록 도구 3개를 실측했다"는 글은 읽는다. 난이도 표시는 콘텐츠가 아니라 **"따라 하기 난이도" 칸**으로만 한다 |
| 10 | 강의와 연결돼도 판매 사이트처럼 안 보이려면? | 무료 콘텐츠가 문제 하나를 **끝까지 해결**한다. 글 중간에 판매 유도가 없다. 교육 안내는 사이트의 한 페이지(강연·교육)와 글 끝의 한 줄로만 한다. 수익화 강의는 팔지 않는다(편집 원칙). 교육 이력도 연구 기록의 일부로 공개한다(§10) |

## 3. 카테고리 설계: A~E 검토 결과

### 3-1. 기존 가설 A~E 평가

| 가설 | 평가 | 판단 |
|---|---|---|
| A. AI BRIEF / AI 변화 | 주제가 아니라 **형식**이다. "회의 기능 변화"는 업무 주제이기도 해서 카테고리로 두면 중복된다 | **형식(BRIEF)으로 전환** |
| B. AI LAB / 직접 실험 | 사이트의 정체성 자체다. 카테고리로 두면 거의 모든 글이 LAB에 들어가 카테고리가 무의미해진다 | **형식(TEST, TRACK)으로 전환** + 사이트 정체성 문장으로 승격 |
| C. AI LIFE / WORK | 사용자가 "내 상황"으로 찾아 들어오는 입구로 강하다. 다만 일, 사업, 생활은 문제 유형이 다르다 | **카테고리로 유지하되 분리**: 일 / 가게·1인 사업 / 생활 |
| D. AI VALUE / 경제 효과 | 모든 TEST에 적용되는 **측정 관점**이다. 카테고리로 두면 C와 중복되고, "돈" 카테고리가 부업 채널처럼 보이는 위험이 있다(Phase 1) | **카테고리가 아니라 모든 실험의 표준 측정 항목(효과 태그)**으로 전환. MAKE 주장 검증은 CHECK 형식으로 다룬다 |
| E. AI GUIDE / KNOWLEDGE | 형식이다. 다만 "AI를 어디까지 믿나, 무엇이 사실인가"라는 주제 묶음은 강하다 | GUIDE는 형식으로 두고, **주장·오해·안전·기본 개념을 묶은 카테고리**를 새로 만든다 |

### 3-2. 최종 제안: 카테고리 4개 (주제 = 독자가 들어오는 입구)

| # | 카테고리 (가칭) | 다루는 것 | 입구가 되는 독자 질문 | 50편 이상 확장 가능성 |
|---|---|---|---|---|
| 1 | **일** | 직장·프리랜서 업무: 문서, 메일, 회의, 자료조사, 보고, 엑셀, 발표 | "이 업무에 AI 써도 되나, 얼마나 줄어드나?" | 높음 (업무 × 도구 × 재검증) |
| 2 | **가게·1인 사업** | 자영업·1인 사업: 홍보 문구, 이미지, 리뷰 답글, 고객 응대, 견적·서류, 지원사업 | "외주 맡길까, AI로 할까? 얼마 아끼나?" | 중간~높음 (업종 × 업무) |
| 3 | **생활** | 행정, 가계, 구매 비교, 여행, 건강 질문 준비, 자녀·부모, 학습 | "이런 것도 AI로 되나? 어디까지 믿어도 되나?" | 높음 (생활 이벤트 × 계절) |
| 4 | **AI 바로 알기** | AI의 차이·한계·틀리는 이유, 개인정보, 요금제, 새 기능의 의미, **AI 관련 주장(수익·광고·유행 팁) 검증**, 사기 예방 | "이 말 진짜야? AI가 뭘 할 수 있고 뭘 못 하나?" | 높음 (주장과 기능은 계속 나옴) |

평가 기준 점검:
- **이해 가능성**: 네 이름 모두 일반인이 바로 이해한다.
- **중복**: "어디에 쓰나(일/사업/생활)"와 "AI에 대한 사실(바로 알기)"로 축이 명확하다. 애매할 때는 **독자가 처한 상황**을 기준으로 분류한다(예: 가게 리뷰 답글 → 가게·1인 사업).
- **1인 운영**: 4개면 매월 순환이 가능하다.
- **교육 연결**: 일·사업은 업무 AI 교육, 생활·바로 알기는 입문·기관 교육과 연결된다.
- **차별화**: 카테고리 자체는 흔하다. 차별점은 형식(TEST·TRACK·CHECK)과 측정 항목에서 나온다.

### 3-3. 가로지르는 효과 태그 (카테고리 아님)

모든 TEST·TRACK·CHECK에 측정 결과를 태그로 붙인다. 사이트에서 "시간 아낀 실험만 보기"처럼 필터로 쓴다.

| 태그 | 의미 | 기록 방식 |
|---|---|---|
| **시간 절약** (SAVE TIME) | 기존 방식 대비 줄어든 시간 | 기준 시간과 AI 사용 시간을 실측, 분 단위 |
| **비용 절약** (SAVE MONEY) | 외주비, 도구비 등 줄어든 비용 | 비교 기준(견적, 시세)의 출처를 명시 |
| **품질 변화** (CREATE VALUE) | 결과물 품질이나 할 수 있는 일의 범위 변화 | 판단 기준을 먼저 공개 |
| **수익 주장** (MAKE MONEY) | 외부의 수익 주장을 검증함 | CHECK 형식만. 매출과 순이익 구분 |
| **효과 없음 / 손해** | 시간이나 비용이 오히려 늘어남 | 숨기지 않는다 |

**초기 중심은 시간 절약과 비용 절약이다.** 수익 주장 검증은 전체의 10% 안팎으로 제한한다(Phase 1 G5 결론).

## 4. 형식(Format) 설계

> **Phase 5A·5B 반영 (2026-09-29)**: 아래 형식 코드는 내부용이다. 독자에게는 한글 라벨(가칭)로 보인다: TEST → 직접 해봄 / TRACK → 오래 써보기 / CHECK → 주장 확인 / BRIEF → 변화 확인 / GUIDE → 알아두기. 상세: [../brand/voice-and-language.md](../brand/voice-and-language.md) §3

카테고리는 "무엇에 대해"이고, 형식은 "어떻게 다루나"다. 한 글은 **카테고리 1개와 형식 1개**를 가진다.

| 형식 | 정의 | 운영자 직접 실행 | 분량·제작 부담 | Evergreen / Timely |
|---|---|---|---|---|
| **TEST** (직접 실험) | 하나의 과제를 AI로 실제 수행하고 측정·판정 | **필수** | 중~상 (4~10시간) | 대체로 Evergreen (단, 도구 버전 의존 → 재검증 대상) |
| **TRACK** (장기 추적) | 7일, 30일, 90일 동안 같은 방법을 반복하며 기록. 중간 업데이트 | **필수** | 기간은 길고 매주 부담은 작음 (주 1~3시간) | Timely하게 진행, 완료 후 Evergreen |
| **CHECK** (주장 검증) | 외부 주장(수익, 기능 광고, 유행 팁)을 원출처부터 확인. 가능하면 직접 실행 | 실행 가능 부분은 필수. 불가능하면 NOT TESTED로 표시 | 중~상 | Timely → Evergreen DB |
| **BRIEF** (변화 판정) | 새 기능·정책·요금 변화를 "무엇이 / 왜 / 나에게 / 써볼까·넘길까"로 판정 | **최소 1회 직접 사용 후 판정** (못 써봤으면 판정 대신 "미사용"으로 표시) | 하~중 (1~3시간) | Timely |
| **GUIDE** (참고 자료) | AI 기본 개념, 안전 기준, 방법론. 사이트 안의 TEST 결과를 근거로 연결 | 가능하면 사이트 내 실험 근거 인용 | 중 | Evergreen (분기별 점검) |

**제외하거나 미룬 형식**
- **CASE (타인의 활용 사례)**: 실제 인물의 동의와 확인이 필요하다. 가짜 사례의 위험이 있어 **초기에는 제외**한다. 이후 실제 인터뷰(Phase 2 인터뷰 설계 재사용)로 확보한 사례만, 동의를 받아 추가를 검토한다.
- "프롬프트 N개", "도구 TOP 10" 같은 목록형: 포화 영역이라 만들지 않는다(Phase 1).

**정기 발행물 (형식과 별도)**
- **주간 노트**: 이번 주 변화 1~2건(BRIEF 요약) + 이번 주 해볼 것 1개 + 진행 중 TRACK 업데이트 + 지난 글 수정 사항. 새 글이 아니라 **기존 콘텐츠를 엮는 단위**다.
- **월간 결산**: 이번 달 써보고 남긴 것과 버린 것, 측정된 절약 시간 합계, 실패 목록.

## 5. 사이트 구조 (정보 구조 수준, UI 아님)

> **Phase 5A에서 대체됨 (2026-09-29 승인)**: 아래 구조는 초기 구상 기록으로 남긴다. 현재 기준은 [site-ia.md](site-ia.md)의 **과제 중심 IA**다.
> - 메인 메뉴: 과제로 찾기 / 이번 주 / 확인 기록 / 방법 (5B 라벨 검수안: 하는 일로 찾기 / 이번 주 / 확인 기록 / 확인 방법)
> - 카테고리는 별도 페이지가 아니라 과제 목록의 묶음 제목
> - 효과 필터는 콘텐츠 100편 이후 (site-ia §12)
> - 글 URL은 형식과 무관한 공통 경로 `/a/{slug}/` (site-ia §14)

```
홈
├─ 이번 주 노트 (최신 주간 노트)
├─ 진행 중인 실험 (TRACK 목록, 다음 업데이트 날짜)
├─ 최근 판정 (TEST·CHECK·BRIEF 최신)
├─ 카테고리: 일 / 가게·1인 사업 / 생활 / AI 바로 알기
├─ 효과 필터: 시간 절약 / 비용 절약 / 효과 없음 / 주장 검증
├─ 연구 기록 (누적 지표, 실험 목록, 실패 목록, 재검증 목록)
├─ 방법과 원칙 (실험 방법론, 편집 정책, 라벨 설명, 정정 로그)
├─ 검증 요청 (독자 요청 접수, 추후)
└─ 소개 · 강연/교육 (운영자 활동 기록, 교육 안내)
```

홈 첫 화면은 뉴스가 아니라 **"이번 주 노트"와 "진행 중인 실험"**이다. 첫 방문자가 바로 "여기는 직접 해보는 곳"이라는 것을 알 수 있게 한다.

## 6. 대표 콘텐츠 표준 구조

### 6-1. TEST (직접 실험) 표준 틀

```
[상단 정보 박스]
- 판정: 쓸 만함 / 조건부 / 비추천  (한 줄 이유)
- 효과 태그: 시간 절약 00분 → 00분 / 비용 ○원 → ○원 / 효과 없음
- 확인일: YYYY-MM-DD
- 사용 도구·버전·요금제: (예: ○○ 무료 / 유료 플랜명)
- 직접 결제 여부: 예 / 아니오(무료) / 무상 제공받음
- 이해관계: 제휴 없음 / 제휴 링크 포함 / 협찬
- 따라 하기 난이도: 쉬움 / 보통 / 어려움
- 상태: 완료 / 업데이트됨(날짜) / 재검증 필요

1. 어떤 문제였나          (누가, 언제, 얼마나 자주)
2. 기존에는 어떻게 했나     (기준 방법, 기준 시간·비용 = baseline)
3. 테스트 설계            (조건, 성공 기준, 사용 자료, 사전에 정한 것)
4. 실제 과정              (입력한 것, 받은 결과, 수정한 것, 원본 스크린샷)
5. 측정 결과              (시간, 비용, 품질. 표로)
6. 실패·수정한 부분         (틀린 답, 다시 시킨 횟수, 사람이 고친 부분)
7. 누구에게 맞나 / 맞지 않나
8. 다시 쓸 것인가          (운영자 본인의 실제 선택)
9. 혼자 해보려면           (무료로 따라 할 수 있는 최소 단계)
10. 한계                 (n=1, 운영자 조건, 도구 변경 가능성)
[하단] 관련 실험 · 이 글의 제작에 AI를 쓴 부분 · 수정 이력
```

### 6-2. 다른 형식의 차이점

| 형식 | TEST 틀과 다른 점 |
|---|---|
| TRACK | 3번에 **기간, 기록 방법, 중단 기준**을 사전 공개한다. 5번은 날짜별 기록표로, 7일·30일·90일 시점마다 업데이트한다. 상태는 "진행 중 (다음 업데이트: 날짜)"으로 표시한다 |
| CHECK | 1~2번 대신 **주장(CLAIM) → 원출처(SOURCE) → 주장의 조건(기간, 매출/순이익, 선행 자산)**을 쓴다. 이어서 직접 실행 가능 여부(TEST 또는 NOT TESTED와 이유) → 비용·시간 → 결과(매출, 순이익 구분) → 한계·위험 → 누구에게 가능/불가능. 확인하지 못한 주장은 **미검증 주장(UNVERIFIED CLAIM)**으로 표시한다([ai-monetization-landscape.md](../research/ai-monetization-landscape.md) §6, §8) |
| BRIEF | 무슨 일인가 → 왜 중요한가 → 나에게 무엇이 달라지나 → **써볼까 / 넘길까**(직접 써본 결과 한 문단) → 확인일·출처. 800~1,500자 |
| GUIDE | 질문 하나에 답 → 근거(사이트 내 TEST 링크, 공식 출처) → 실천 기준 → 마지막 점검일 |

**이 구조 자체가 신뢰 장치다.** 칸을 비울 수 없으니 해보지 않은 것은 쓸 수 없고, 해본 것은 비교할 수 있다.

## 7. 신뢰 시스템

### 7-1. 라벨: 최소 세트 (남발 금지)

글마다 **해당하는 것만** 표시하고, 목록 화면에서는 최대 2개만 보여준다. "검증됨(VERIFIED)"은 효과 보증으로 읽힐 수 있어 **쓰지 않는다.**

| 종류 | 라벨 | 의미 |
|---|---|---|
| 실행 | **직접 사용** | 운영자가 해당 도구로 과제를 직접 수행함 (TEST·TRACK의 기본값이라 목록에서는 생략 가능) |
| 실행 | **직접 결제** | 유료 기능을 운영자 비용으로 사용함 |
| 실행 | **실험 안 함** | 윤리·법적 이유로 의도적으로 실행하지 않음 (예: 선불 수익 보장 상품) |
| 근거 | **근거 확인** | 외부 주장의 원출처·증빙을 확인함 (효과 보증 아님) |
| 근거 | **미검증 주장** | 증빙을 확인할 수 없는 주장 |
| 상태 | **진행 중** | TRACK 진행 중. 다음 업데이트 날짜를 함께 표시 |
| 상태 | **업데이트됨** | 결과나 도구가 바뀌어 수정함 (날짜) |
| 상태 | **재검증 필요** | 도구·요금이 바뀌어 결과가 달라졌을 수 있음 |
| 결과 | **기대 미달** | 주장이나 기대만큼의 결과가 나오지 않음 (주장 대비 기준) |
| 이해관계 | **제휴 없음** / **제휴 포함** / **협찬·무상 제공** | 경제적 이해관계 표시 (추천·보증 심사지침 수준 이상) |

### 7-2. 사이트 차원의 신뢰 장치

> **Phase 5A 반영**: 연구 기록, 실패 목록, 정정 로그는 MVP에서 **"확인 기록" 한 페이지의 섹션**으로 통합한다(진행 중 / 최근 확인 / 기대 미달·중단 / 업데이트 / 정정). 사용 도구 목록은 소개 페이지의 한 섹션으로 둔다. 초기에는 총계 숫자를 크게 보여주지 않는다(site-ia §10). 카드에 보이는 메타정보는 결론, 측정값 1개, 확인 방식, 확인한 날로 줄인다(site-ia §7).

| 장치 | 내용 |
|---|---|
| 방법론 페이지 | 실험 설계 원칙, 측정 방법, 판정 기준, 라벨 정의 |
| 연구 기록 페이지 | 실험·검증 목록과 누적 지표 (§9) |
| 실패 목록 | 기대 미달·효과 없음 결과만 모아서 공개 |
| 정정 로그 | 틀린 내용과 수정 내역을 날짜별로 공개 |
| 사용 도구 목록 | 운영자가 실제로 쓰는 도구와 요금제, 사용 시작일 (결제 사실 기반) |
| 원자료 보관 | 시간 기록, 스크린샷, 영수증을 보관하고 가능한 범위에서 공개 |
| 확인일 표시 | 모든 사실성 콘텐츠에 표시 |

## 8. 반복 방문 시스템

| 후보 | 재방문 이유의 강도 | 1인 지속 가능성 | 판단 |
|---|---|---|---|
| **주간 노트** (변화 1~2 + 해볼 것 1 + 실험 업데이트) | 강함. 고정된 요일에 오는 습관 슬롯 (순살의 시스템 원리) | 높음 (기존 콘텐츠를 엮는 것, 2~3시간) | **핵심 채택** |
| **진행 중인 실험 (TRACK)과 7일·30일 업데이트** | **강함. "다음 결과"가 존재함** | 중간 (동시 1~2건 제한) | **핵심 채택** |
| 이번 주 직접 해볼 AI 한 가지 | 중간~강함 (행동 유도) | 높음 | 주간 노트에 포함 |
| 새 기능 실제 테스트 (BRIEF) | 중간 (이벤트성) | 중간 (속보 경쟁 금지, 월 2~4건) | 채택, 선별 |
| 월간 결산 (남긴 것·버린 것, 절약 시간 합계, 실패 목록) | 중간 (월 1회 정리 욕구) | 높음 | **채택** |
| 이전 콘텐츠 재검증 ("6개월 뒤 다시 해봤다") | 중간 (기존 독자의 후속 관심) | 중간 (분기 2~3건) | 채택 (연구 이력에도 핵심) |
| 실패한 실험 기록 | 중간 (호기심, 신뢰) | 높음 (TEST의 부산물) | 별도 목록으로 채택 |
| 실제 시간 절약 기록 (운영자 본인 누적) | 중간 (서사적 재미, 신뢰) | 높음 (TRACK의 부산물) | 월간 결산에 포함 |
| 독자가 요청한 검증 | 강함 (참여, 소유감) | 중간 (선별 필요) | **독자가 생긴 뒤 시작** (오픈 3개월 후 검토) |
| AI 서비스 가격·기능 변화 업데이트 | 약함~중간 (대체재 많음) | **낮음 (유지 부담 큼)** | 운영자가 쓰는 도구에 한해 월간 결산에 한 줄로만 |
| 월간 BEST / WORST | 중간 | 높음 | 월간 결산에 통합 |

**권고 조합**: 주간 노트(매주 같은 요일) + 진행 중 TRACK 1~2건 + 월간 결산 + 분기 재검증.

**채널 주의**: 주간 노트를 어떤 채널로 보낼지(이메일, 카카오톡 채널, 웹만)는 **아직 정하지 않는다.** Phase 2 인터뷰 P3(정기 수신 습관)에서 확인할 항목이다. 이번 단계에서는 "웹에 주간 노트 페이지가 쌓인다"까지만 전제한다.

## 9. 운영자의 연구 이력 축적 방식

### 9-1. 원칙
- 모든 TEST, TRACK, CHECK, BRIEF 글은 표준 메타데이터(형식, 확인일, 도구, 결과 라벨, 효과 태그, 결제 여부)를 가진다. **지표는 이 메타데이터에서 자동으로 계산**하고, 손으로 부풀릴 수 없게 한다.
- 모든 숫자는 **클릭하면 해당 글 목록이 나와야** 한다. 목록이 없는 숫자는 쓰지 않는다.
- **현재 수치는 0이다.** 아무것도 만들어내지 않는다.

### 9-2. 지표 설계와 허영 지표 점검

| 지표 | 의미 있는 이유 | 허영 위험 | 보완 규칙 |
|---|---|---|---|
| 직접 실험 수 (TEST + TRACK) | 실행의 양 | 쉬운 실험을 많이 해서 부풀릴 수 있음 | 표준 틀을 모두 채운 것만 센다. 형식별로 나눠서 표시 |
| 장기 추적 완료 수 | 지속적 연구의 증거 | 낮음 | 중단한 실험도 "중단"으로 따로 표시 |
| 실패·기대 미달 공개 수 | 정직성의 증거 | 낮음 (의도적 실패 유도 가능성은 있음) | 전체 대비 비율과 함께 표시 |
| 재검증 수 | 결과를 갱신하는 연구 태도 | 낮음 | 결과가 바뀐 건수를 함께 표시 |
| 확인한 외부 주장 수 (CHECK) | 판별 능력 | 쉬운 주장만 고를 수 있음 | 미검증·실험 안 함 결과도 포함해 표시 |
| 측정된 절약 시간 합계 (운영자 본인 실측) | 경제 효과의 실제 기록 | 과장 가능 | **실측 기록이 있는 것만.** 추정치는 합산하지 않는다 |
| 테스트한 AI 도구 수 | 범위 | **높음** (한 번 열어본 것도 셀 수 있음) | 표준 TEST를 1건 이상 수행한 도구만 센다. 단독으로 내세우지 않는다 |
| 정정 건수 | 투명성 | 역설적으로 신뢰 요소 | 숨기지 않는다 |
| 연속 발행 기간 (주간 노트) | 지속성 | 낮음 | 결호도 표시 |
| 강의·교육 횟수, 수강 인원 | 교육 활동 이력 | 부풀릴 수 있음 | **실제 진행한 것만.** 기관명은 허락 후 공개 |
| 조회수, 구독자 수 | 인기 | 높음 | 연구 이력 지표로 쓰지 않는다 |

1년 뒤 운영자가 할 수 있어야 하는 말의 **형태**(숫자는 실제로 쌓인 것만):
> "지난 ○개월 동안 AI로 업무·생활 과제 ○건을 직접 실험하고, 그중 ○건은 기대 미달로 기록했습니다. 장기 추적 ○건, 외부 주장 검증 ○건, 재검증 ○건을 했고, 모든 기록은 확인일과 함께 공개되어 있습니다."

## 10. 교육 연결 원칙

| 원칙 | 구체 규칙 |
|---|---|
| 무료 콘텐츠가 문제 하나를 끝까지 해결한다 | TEST의 "혼자 해보려면" 칸에 무료로 따라 할 수 있는 최소 단계를 **빠짐없이** 쓴다. 핵심 단계를 숨기지 않는다 |
| 판매 유도를 본문에 넣지 않는다 | 글 중간 배너나 팝업 없음. 교육 안내는 글 끝 한 줄("이 주제로 워크숍·강연 문의") + 소개·교육 페이지 |
| 교육이 필요해지는 지점은 글로 해결하기 어려운 것이다 | "내 업무·가게에 맞게 적용", "막힌 곳을 같이 풀기", "함께 실습하는 습관 만들기" |
| 교육 이력도 공개 기록으로 | 강의 횟수, 대상 유형, (동의받은) 후기를 연구 기록 페이지에 실제 발생한 만큼만 |
| 판매하지 않는 교육 | 수익화 강의("○○로 월 N만원"). 검증 대상과 경쟁하는 교육은 하지 않는다 |
| 우선 경로 | Phase 1·2 가설에 따라 **기관·기업 출강(B2G/B2B)**이 먼저일 가능성이 크다. 사이트는 기관 담당자가 보는 **포트폴리오** 역할을 한다(Phase 2 P5에서 검증) |

자연스러운 흐름:
`콘텐츠(측정된 결과) → 독자가 직접 시도 → 작은 성공 또는 막힘 → "내 상황에서는?" → 워크숍·강연 (개인) / 기관 교육 (기관 담당자가 사이트를 보고 문의)`

## 11. 1인 발행 운영안

작업 시간은 Phase 1 추정치(TEST 4~10시간, BRIEF 1~3시간, GUIDE 3~6시간, 주간 노트 2~3시간)를 기준으로 한 [INFERENCE]다. 첫 8주 동안 실측해서 보정한다.

| 항목 | 주 1편 | **주 2편 (권고)** | 주 3편 |
|---|---|---|---|
| 월 콘텐츠 수 | 4~5편 + 주간 노트 4 | 8~9편 + 주간 노트 4 | 12~13편 + 주간 노트 4 |
| 구성 예 | TEST·CHECK 3 + BRIEF·GUIDE 1~2 | TEST·CHECK·TRACK 4 + BRIEF 2~3 + GUIDE 2 | TEST 5~6 + BRIEF 4 + GUIDE 3 |
| 주당 예상 작업 | 8~12시간 | **15~22시간** | 25~35시간 |
| 품질 | 높음 | 높음~중간 | 실험 품질 하락 위험 |
| 월 실험 수 | 3 | 4 (+ TRACK 1) | 5~6 (측정이 얕아짐) |
| 지속 가능성 (1년) | 높음 | **중간~높음 (버퍼 필요)** | 낮음 (번아웃) |
| 반복 방문 효과 | 약함 (갱신이 느림) | 적정 | 강하지만 품질과 교환 |

**권고안**
- **기본: 주 2편 + 주간 노트.** 그중 1편은 반드시 TEST·CHECK·TRACK 업데이트(직접 실행형)이고, 나머지 1편은 BRIEF나 GUIDE다.
- **오픈 전 버퍼**: Launch Set(12편) + 예비 원고 4편을 확보한 뒤 오픈한다.
- **하향 규칙**: 2주 연속으로 주 22시간을 넘기면 주 1편 + 주간 노트로 내린다. **주간 노트는 결호하지 않는 것**을 최우선으로 한다(습관 슬롯).
- **동시 진행 TRACK은 최대 2건.**
- 운영자의 실제 가용 시간(Founder Input F5)을 받으면 다시 조정한다.

## 12. 기존 Phase 2 인터뷰 설계와의 관계

삭제하지 않는다. 미디어 운영 관점에서 다음과 같이 **재배치**한다.

| 유지 항목 | 미디어에서의 쓰임 |
|---|---|
| User Stage 분류 (S0~S5) | 독자 이해 틀. 콘텐츠의 "따라 하기 난이도"와 "누구에게 맞나" 칸을 쓸 때의 기준 |
| Consumer C2 (최근 문제 사례) | **콘텐츠 백로그의 가장 좋은 공급원.** 실제 사람의 문제가 TEST 주제가 된다 |
| P3 정기 수신 습관 (C4) | 주간 노트의 채널 결정 (이메일, 카톡, 웹) |
| P1 복귀 계기, 경로 A/B/C | 유입 전략 (공유 단위, 오프라인 교육 연계) |
| Buyer Track (P5) | 기관 교육 연결과 포트폴리오 설계 |
| 증거 기록 템플릿, 가상 발언 금지 원칙 | 모든 사례 콘텐츠의 원칙으로 확장 (CASE 형식 도입 시) |
| Target Selection Framework | 최종 "타깃"보다 **카테고리 우선순위와 입구 선정**에 활용 |

조정 제안: 15~20명 규모 인터뷰를 오픈 전에 모두 끝내기보다, **P1·P3·P5 중심의 6~8명 소규모 라운드**를 오픈 전후에 진행한다. 결과는 카테고리 우선순위와 주간 노트 채널에 반영한다. (결정은 사용자에게 — [README](../README.md) 다음 단계)
