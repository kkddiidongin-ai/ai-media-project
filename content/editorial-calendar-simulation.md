# 4주 운영 시뮬레이션 (가상 편집 캘린더)

작성일: 2026-09-29 · 목적: **Media Engine이 1인 운영에서 실제로 굴러가는지 검증**
관련 문서: [../strategy/media-engine.md](../strategy/media-engine.md) · [editorial-workflow.md](editorial-workflow.md) · [launch-content-set.md](launch-content-set.md) (§6 교체안 기준) · [content-backlog.md](content-backlog.md)

> - **실제 실험 결과, 판정, 수치는 하나도 적지 않았다.** 이 문서가 다루는 것은 "무엇을 언제 하고 몇 시간 걸리나"뿐이다.
> - 시간은 Phase 1~2B 추정치를 바탕으로 한 **범위 가설**이다. 운영자의 실제 가용 시간(Founder Input F5)은 아직 받지 못했다. 상한은 **주 15~22시간**으로 가정했다.
> - 번호는 백로그 번호다.

## 0. 전제

- 오픈 시점(W0)에 Launch Set 12편(§6 교체안)과 주간 노트 1호가 발행되어 있다.
- TRACK 9번(주간 업무보고 30일)은 **오픈 2주 전에 시작**해서, W1 시작 시 15일째다.
- 동시 진행 TRACK은 최대 2건, HIGH 난이도는 2주에 1편 이하, TRACK 최종 주에는 HIGH 금지 (media-engine §13-4, §7).
- 주간 목표: 직접 실행형 1편 + 가벼운 1편 + 주간 노트.

## 4. 판단

- **엔진은 1인 운영에서 굴러간다**(조건: 주 15~22시간, HIGH 분할, 동시 TRACK 2건 이하, 업데이트 예산 상한).
- 가장 위험한 지점은 ① TRACK 종료 주의 겹침 ② 월말(결산 + 점검) 주의 겹침 ③ 오픈 준비 기간의 과소평가다.
- 운영자의 실제 가용 시간이 주 15시간 미만이면 **주 1편 + 주간 노트**로 시작하고, TRACK은 동시 1건으로 제한해야 한다.
